# Commit Message Convention

HIRELINK Backend의 커밋 메시지는 Conventional Commits 형식을 기본안으로 제안합니다. 세부 표기 방식은 팀 합의에 따라 조정할 수 있으며, 아직 확정된 팀 규칙을 의미하지 않습니다.

## 기본 형식

```text
type: 변경 내용을 간결하게 설명
```

필요하면 본문과 이슈 참조를 추가할 수 있습니다.

```text
type: 변경 내용을 간결하게 설명

변경 이유 또는 구현 시 고려한 내용을 작성합니다.

Refs: #이슈번호
```

## Type

| Type | 설명 |
| --- | --- |
| `feat` | 새로운 기능 |
| `fix` | 버그 수정 |
| `refactor` | 리팩터링 |
| `docs` | 문서 수정 |
| `chore` | 환경 설정 및 기타 작업 |
| `test` | 테스트 |

## 작성 기준 제안

- 제목은 변경 결과가 드러나도록 간결하게 작성합니다.
- 한 커밋에는 가능한 한 하나의 논리적 변경을 담습니다.
- 제목 끝에는 마침표를 붙이지 않는 방식을 권장합니다.
- 구현 내용만으로 이유를 알기 어렵다면 본문에 배경과 판단 근거를 작성합니다.
- 이슈를 바로 종료해야 하는 경우에는 PR 본문에서 `closes #이슈번호`를 사용하는 방식을 권장합니다.
- 선택적으로 `feat(auth): 로그인 구현`처럼 scope를 사용할 수 있지만, scope 목록은 팀에서 필요할 때 합의합니다.

## 예시

```text
feat: 채용 공고 등록 기능 추가
fix: 만료된 리프레시 토큰 검증 오류 수정
refactor: 인증 서비스의 토큰 발급 책임 분리
docs: 로컬 실행 방법 보완
chore: Gradle 의존성 설정 정리
test: 회원가입 중복 요청 통합 테스트 추가
```

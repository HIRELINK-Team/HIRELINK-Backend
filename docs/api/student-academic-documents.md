# 성적·TOPIK 증명서와 유학생 탈퇴

기존 [재학증명서 API](./student-enrollment.md)와 같은 비공개 `student-documents` 버킷, 5MB 제한, PDF/JPEG/PNG 업로드를 사용한다. OCR은 정보 추출이며 서류 진위 확인이 아니다. 실제 학교별 서식의 인식 품질은 운영 전 별도 확인한다.

## 성적·TOPIK API

JWT 인증이 필요하며 본인의 활성 유학생 프로필만 사용할 수 있다. 아래 `{kind}`는 `transcript` 또는 `topik`이다.

| 메서드·경로 | 입력·결과 |
| --- | --- |
| POST `/api/students/me/documents/{kind}/preview` | multipart `file`. `draftId`와 `extracted` 반환. 프로필과 최종 원본은 그대로 유지 |
| POST `/api/students/me/documents/{kind}/{draftId}/confirm` | 수정값 요청 본문 없음. 본인의 해당 종류 최신 초안만 확정. 프로필·원본 교체 후 이전 원본 삭제 |
| GET `/api/students/me/documents/{kind}` | 최종 확정된 결과만 반환. 미확정이면 404 |

세 API 모두 성공 시 **200 OK**, `Content-Type: application/json`, `Cache-Control: no-store`를 반환한다.
`kind`는 소문자 `transcript`(성적증명서), `topik`(TOPIK 성적증명서)만 허용한다. `enrollment`는 별도 재학증명서 API이며 이 응답 스키마를 사용하지 않는다.

| 응답 필드 | 미리보기 | 최종 등록·조회 |
| --- | --- | --- |
| `documentType` | `TRANSCRIPT` 또는 `TOPIK` | 동일 |
| `draftId` | 최종 등록에 사용할 UUID | `null` |
| `extracted` | 이번 OCR 추출 결과 | 최종 등록한 추출 결과 |
| `registeredAt` | `null` | 최종 등록 시각(UTC, ISO 8601) |

성적증명서 미리보기 응답 예시:

```json
{
  "documentType": "TRANSCRIPT",
  "draftId": "ad0856ec-3b1e-4d1d-88cd-1f5063aa2720",
  "extracted": {"academicYear": 2025, "semester": "SECOND", "averageGpa": 4.24, "topikLevel": null},
  "registeredAt": null
}
```

TOPIK 미리보기 응답 예시:

```json
{
  "documentType": "TOPIK",
  "draftId": "ad0856ec-3b1e-4d1d-88cd-1f5063aa2720",
  "extracted": {"academicYear": null, "semester": null, "averageGpa": null, "topikLevel": 4},
  "registeredAt": null
}
```

최종 등록·조회는 위 종류별 `documentType`, `extracted` 구조를 그대로 사용하고 `draftId`는 `null`, `registeredAt`은 `"2026-11-29T03:00:00Z"`와 같은 등록 시각을 반환한다. Swagger의 각 API에는 성적증명서와 TOPIK 성공 예시를 모두 제공한다.

- 성적은 문서에 명시된 학기 중 가장 최근 학기의 **평균 학점**이다. 인쇄된 마지막 행이나 누적 평점을 대신 사용하지 않는다. 만점 기준 저장·환산은 하지 않는다. `semester`는 `FIRST`, `SUMMER`, `SECOND`, `WINTER`이다.
- 현재 파서는 학년도·학기 표기와 평점평균/평균평점/평균학점/GPA 라벨이 있는 한국어 학기 서식을 지원한다. 최신 학기의 평균을 특정하지 못하거나 후보가 충돌하면 422로 재업로드를 안내한다. 임의의 과거 학기 값을 사용하지 않는다.
- TOPIK은 1~6급만 저장한다. 응답은 `topikLevel` 외 추출 필드가 null이다.
- 프로필 PATCH와 온보딩의 `topikLevel` 입력은 **숫자·null 모두 400**이다. 확인된 TOPIK 값은 해당 서류의 최종 등록으로만 갱신한다. 한국어 자기평가 수준은 기존처럼 수정할 수 있다.
- 최종 확정 전에 이탈하거나 저장·검증이 실패하면 기존 확정 정보와 원본을 유지한다. 동일 초안 중복 확정은 409다. 다른 서류 종류는 변경하지 않는다.
- 종류별 최신 확정 원본 한 개와 확인 대기 초안을 구분한다. 이전 파일은 DB 커밋 이후 삭제하며 실패하면 기존 정리 큐에서 재시도한다. 원본 경로나 공개 URL은 응답에 포함하지 않는다. 개별 삭제 API는 없다.
- 401 인증, 403 비유학생/탈퇴, 404 미등록, 409 초안 없음·교체됨, 413 5MB 초과, 415 파일 형식, 422 추출 불가, 502 OCR·저장소 오류. 오류 응답은 기존 `{code,message}` 형식이다.

## 필수 정보 미인식 안내

업로드와 최종 확인에서 필수 정보를 검증한다. `422 UNREADABLE_STUDENT_DOCUMENT`와 기존 `{code,message}` 형식은 유지하고, `message`에 다음 항목을 구분하여 안내한다.

- 성적: `직전 학기 평균 학점을 확인하지 못했습니다. 해당 정보가 선명하게 보이도록 다시 촬영하거나 파일을 올려주세요.`
- TOPIK: `TOPIK 등급을 확인하지 못했습니다. 해당 정보가 선명하게 보이도록 다시 촬영하거나 파일을 올려주세요.`

성적의 학년도·학기 표기 미인식으로 가장 최근 학기를 특정하지 못해도 직전 학기 평균 학점 확인 실패로 안내한다. 과거 학기·누적 평점·임의 기본값을 사용하지 않는다. 파일 손상·서류 유형 미인식은 기존 일반 재업로드 안내를 유지한다. 내부 OCR 응답 원문이나 문서 내용은 공개하지 않는다.

프론트는 오류의 `message`를 표시하고 재촬영·재업로드로 연결한다. 오류가 난 서류는 최종 등록할 수 없고, 기존 확정 원본·프로필·서류 완성률·배지는 이 오류로 변경하지 않는다. 백엔드와 OCR 이미지를 함께 갱신해야 하며 DB 구조 변경은 없어 추가 Flyway 마이그레이션은 없다.

## 탈퇴·복구

`POST /api/students/me/withdrawal`에 JWT와 `{"confirmed":true}`를 전송한다. 응답은 `requestedAt`, `recoveryDeadline`이다.

1. 요청 즉시 휴면으로 표시하고 refresh token을 삭제한다. JWT의 계정 버전을 변경하므로 이전 access/refresh token은 복구 후에도 재사용할 수 없다. 원본과 소셜 연결은 유지한다.
2. 요청 이후 새로 수행한 소셜 인증의 결과 교환이 30일 경계 **이전**에 완료되면 복구한다. 탈퇴 전에 발급된 가입/로그인 세션으로 복구할 수 없다.
3. 30일 경계부터 복구를 거절한다. 정리 작업은 세 종류의 확정 원본·초안·대기 삭제 파일을 실제 삭제하고 Google/Kakao 연결을 해제한 뒤 로컬 인증 연결을 제거한다. 외부 실패 시 완료로 표시하지 않고 재시도한다.
4. 최종 탈퇴 시 이름·이메일·전화번호·인증 완료 시각은 DB에 보존한다. 일반 회원 접근자는 최종 탈퇴한 계정의 이름·이메일·전화번호를 반환하지 않는다. 확정 서류 기록은 `deleted_at`을 기록하고 파일 위치·미확정 초안을 비운다. 확정 추출값·등록 시각은 남기되 일반 서류 조회에서 제외한다. 최종 등록하지 않은 초안만 있는 서류 행과 임시 전화번호 인증·등록증 갱신 정보는 제거한다.
5. 보관기한 `withdrawal_retain_until`은 **최종 탈퇴가 성공한 시각에서 한국 시간 기준 3년 뒤**다. 윤년 2월 29일은 3년 뒤 2월 28일의 같은 시각으로 계산한다. 원본/소셜 연결 정리가 실패해도 30일 복구 기한은 늘어나지 않는다.
6. 보관기한 이상이 되면 정리 스케줄러가 회원 개인정보, 프로필 값(저장된 근무 가능 조건 포함), 확정 서류 기록, 등록증 인증 기록, 경력, 매칭 조건, 약관 동의, 전화번호 인증/요청 기록을 하나의 트랜잭션에서 삭제한다. 오류 시 전체 DB 정리를 롤백하고 다음 실행에서 재시도한다. `retained_data_purged_at`으로 완료를 기록하며, 회원·프로필 식별 행과 탈퇴/정리 시각은 FK 관계 및 정리 이력 유지를 위해 남긴다.
7. 정상 회원과 30일 휴면 회원의 전화번호 중복은 계속 차단한다. 최종 탈퇴한 회원만 중복 검사·DB 고유 인덱스에서 제외하므로 같은 소셜 계정·전화번호로 새 계정 가입이 가능하다. 과거 동의·등록증 인증·프로필·서류·온보딩 상태를 새 회원으로 복사하지 않는다.

전체 서비스의 모든 개인정보 삭제를 의미하지 않는다. 지원·제안·매칭·추천·알림 및 문자 발송 이력에 복사된 데이터, 외부 로그·백업과 프로필 이미지 실제 객체의 보관/삭제는 별도 연결 범위다. 프로필 이미지 위치 값은 3년 정리 대상이지만 현재 프로필 이미지 객체의 저장소 삭제 경로는 제공하지 않는다. 분석용 조회 API나 관리자 보존자료 열람 API도 추가하지 않는다. 개인정보 보관 근거와 처리방침 적용은 실제 운영 전에 확인한다.

## 사업주의 매칭 유학생 원본 열람

`GET /api/employers/me/matches/{matchId}/student-documents/{kind}`

- 사업주 JWT가 필요하다. `kind`는 `enrollment`, `transcript`, `topik`만 허용한다.
- 요청한 매칭이 삭제되지 않은 채용 완료 매칭이고, 로그인한 사업주의 공고에 속해야 한다. 유학생 ID나 저장소 경로를 요청으로 받지 않는다.
- 같은 사업주와 유학생 사이에 여러 매칭이 있어도 삭제된 매칭 ID는 사용할 수 없다. 남아 있는 유효한 매칭 ID를 사용한다. 지원 중·제안 대기만으로는 열람 권한이 생기지 않는다.
- 유학생이 탈퇴를 신청했다면 신청 시각부터 정확히 30일 **이전**까지 허용한다. 30일 경계부터는 정리 작업이 늦어 파일이 남아 있어도 차단한다. 최종 탈퇴·복구 기한을 확인할 수 없는 탈퇴 계정도 차단한다.
- 현재 배지는 원본 열람 조건이 아니다. 근무 가능 시간 조회의 배지 조건과 구분한다.
- 해당 종류의 최신 **최종 등록** 원본만 제공한다. 새 업로드의 확인 대기 중에는 기존 확정 원본을 제공하며 최종 확인 성공 이후 새 원본을 제공한다. 외국인등록증·미확정 초안·논리 삭제된 서류는 제공하지 않는다.
- 성공 응답은 JSON/서명 URL 대신 `application/pdf`, `image/jpeg`, `image/png` 바이너리다. 원본을 이미지로 변환하지 않는다. `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, 일반 파일명의 `Content-Disposition: inline`을 사용한다. 모든 새 요청에서 권한을 검사한다.
- 서비스 화면은 원본 열람만 제공하며 다운로드·파일 저장 버튼, 메뉴, 링크를 제공하지 않는다. 별도의 다운로드 API나 `attachment` 응답은 추가하지 않는다.
- 프론트는 Bearer 인증을 포함해 파일을 요청하고 응답 Blob을 앱 내부 뷰어에 연결한다. 다운로드·저장 도구를 노출하지 않도록 제어할 수 있는 뷰어를 사용한다. 파일을 새 탭이나 브라우저 기본 PDF 뷰어로 바로 열면 기본 다운로드 도구가 나타날 수 있으므로 해당 방식으로 연결하지 않는다. 저장소 URL·키를 받거나 공개 버킷을 사용하지 않는다.
- 위 화면 동작은 프론트 연동 범위이며 백엔드의 `inline` 헤더만으로 완료되지 않는다. 브라우저가 열람을 위해 원본 데이터를 받는 구조이므로, 기술적인 원본 저장이나 캡처를 완전히 차단하는 보안 기능은 아니다. `no-store`도 저장 금지 기능이 아닌 캐시 제어다. 이미 전달된 사본은 회수할 수 없다.
- 비공개 버킷 여부와 파일 형식·5MiB 한도를 다시 검사한다. 리다이렉트는 따라가지 않는다. 원본 열람은 서류·지원·제안·매칭 상태를 변경하지 않는다.

| 상태 | 오류 코드·의미 |
| --- | --- |
| 400 | `INVALID_INPUT`: 잘못된 매칭 ID, `INVALID_DOCUMENT_TYPE`: 허용하지 않는 서류 종류 |
| 401 | 로그인 필요 또는 유효하지 않은 로그인 세션 |
| 403 | 비사업주·다른 사업주의 매칭·탈퇴 계정·유학생 복구 기한 경과 또는 최종 탈퇴 |
| 404 | `EMPLOYMENT_MATCH_NOT_FOUND`: 없거나 삭제된 매칭, `DOCUMENT_NOT_REGISTERED`: 최종 등록 서류 없음 |
| 502 | `STUDENT_DOCUMENT_STORAGE_FAILED`: 비공개 설정·다운로드·원본 형식/크기 검사 실패 |

오류는 기존 `{code,message}` JSON 형식이며 저장소 응답 원문·비밀키·파일 위치는 노출하지 않는다. 기존 매칭 삭제 상태와 서류 등록 상태를 사용하므로 이 API에 추가 Flyway 마이그레이션은 없다. 실제 운영 저장소를 통한 인증 다운로드와 프론트 뷰어 연결은 별도 확인한다.

## 운영 설정과 확인

- `STUDENT_WITHDRAWAL_ENABLED=true`: 아래 자격 증명 준비 후 탈퇴 신청과 정리 스케줄러 활성화. 기본값은 false이며 이때 신청은 503이다. 기존 로그인은 유지된다.
- `SOCIAL_TOKEN_ENCRYPTION_KEY`: 암호학적 난수 **32바이트의 Base64**, JWT 키와 별도 관리. Google refresh token은 AES-256-GCM으로 암호화해 저장하며 사용자 소셜 식별자에 결합한다. 이 키를 분실/임의 교체하면 기존 연결 해제를 처리할 수 없다.
- `KAKAO_ADMIN_KEY`: 해당 서비스 앱의 사용자 연결 해제 권한이 있는 관리자 키. 저장소나 로그에 기록하지 않는다.
- 활성화 시 유학생 Google 로그인에 offline/consent를 요청해 연결 해제용 refresh token을 확보한다. 기존 Google 회원에게 자격 증명이 없으면 탈퇴 신청에 `409 SOCIAL_REAUTH_REQUIRED`를 반환하고 새 소셜 로그인을 요구한다. 회원 가입 대기 세션의 암호화 값은 가입 완료 시 인증 계정으로 승계한다.
- `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, 비공개 `student-documents` 버킷 연결 및 OCR 컨테이너 배포를 확인한다. 실제 업로드→결과→확정, 실제 공급자 연결 해제는 CI의 모의 호출만으로 검증되지 않는다.
- Flyway V31은 기존 재학증명서 테이블에 종류별 복합 키와 성적/TOPIK 필드를 추가한다. V32는 기존 사용자·인증·소셜 세션 테이블에 탈퇴 시각·계정 버전·암호화 자격 증명 필드를 추가한다. 기존 Flyway 파일은 변경하지 않는다.
- Flyway V42는 3년 보관기한·정리 시각·서류 논리 삭제, 개인정보 제거 후 식별 행 유지용 제약조건, 최종 탈퇴 계정을 제외한 전화번호 고유 인덱스를 추가한다. 기존 최종 탈퇴 계정에는 기존 최종 탈퇴 시각으로 보관기한을 채우며 이미 삭제한 값·원본은 복원하지 않는다. 적용 이전에 이미 3년이 지난 계정은 다음 정리 실행 대상이다.
- 기존 탈퇴 스케줄러는 기본 1분 간격으로 30일 최종 탈퇴와 3년 보관기한 경과 정리를 각각 최대 20건 처리한다. 실제 정리는 다음 실행에서 이루어지며 실패·대기 건수에 따라 늦어질 수 있다. `STUDENT_WITHDRAWAL_ENABLED=false`이면 둘 다 실행하지 않는다.

# 약관 동의 버전 저장·조회

현재 모든 약관은 `v1`만 제공하며 본문·번역은 프론트에서 관리한다. 백엔드는 약관 종류, 필수 여부, 현재 본문 버전과 회원이 실제 확인한 버전의 동의 여부·시각을 관리한다. 본문 API와 개정 약관 재동의 기능은 제공하지 않는다.

## 조회

| API | 인증 | 용도 |
| --- | --- | --- |
| GET /api/auth/social/terms | 가입 진행 쿠키 | 가입 대상 약관과 임시 동의 기록 |
| GET /api/users/me/term-agreements | Bearer | 전체 약관 메타데이터와 로그인 회원 본인의 기록 |
| GET /api/users/me/term-agreements/location | Bearer | 위치 약관 메타데이터와 본인의 기록 |

응답은 `Cache-Control: no-store`이며 조회만으로 동의 행을 만들거나 변경하지 않는다.

- `currentVersion`: 해당 항목의 현재 적용 본문 버전. V38 초기화 이후 기존 약관은 `v1`이다.
- `agreedVersion`: 저장된 동의 여부에 대응하는 본문 버전. 과거 버전 미기록 또는 가입 시 선택 항목 생략은 null.
- `isAgreed`, `agreedAt`: 기존 동의 여부·시각. `agreedVersion=null`만으로 미동의라고 판단하지 않는다.
- 본문을 조회한 것만으로 기존 동의 여부·시각·버전을 변경하지 않는다.
- 동의하지 않은 항목을 명시적으로 전송한 경우에도 표시한 본문의 버전은 저장하며, 동의 시각은 null이다.

회원 조회는 본인만 가능하며 인증 없음은 401, 탈퇴 계정은 403이다. 온보딩 중 위치 동의에도 사용하므로 이 API에 온보딩 완료를 요구하지 않는다.

## 저장

두 PUT API에 `version`이 필수다. 서버가 현재 버전을 자동으로 채워서는 안 된다.

```json
{"agreements":[{"termTypeId":4,"isAgreed":true,"version":"v1"}]}
```

약관 ID는 조회 응답을 사용한다. 프론트는 현재 `v1` 본문을 보여주고 `version: "v1"`을 전달한다. 서버는 요청에 버전이 없으면 자동으로 채우지 않으며 저장된 현재 버전과 일치하는지 검사한다. 버전 필드 형식은 영문 또는 숫자로 시작하는 1~64자의 영문·숫자·점·밑줄·하이픈이다.

- `PUT /api/auth/social/terms`: 필수 약관 전체 true, 생략한 선택 약관은 false/null 버전. 같은 버전의 true 반복은 시각을 유지한다.
- `PUT /api/users/me/term-agreements`: 요청 항목만 갱신한다. 같은 버전의 기존 동의 시각은 유지한다. 이미 동의한 기록을 다른 버전으로 덮어쓰는 기능은 제공하지 않는다. 과거 버전 미기록 true에 임의로 이름을 붙이는 요청도 차단한다.
- 하나라도 검증 또는 저장에 실패하면 요청 전체를 롤백한다.
- 소셜 전화번호 인증으로 계정을 생성할 때 가입 세션의 실제 버전·시각을 그대로 정식 기록에 옮긴다. 그 사이 현재 버전이 변경돼도 새 버전으로 바꾸지 않는다.
- 배포 전에 만들어져 필수 동의 버전이 없는 가입 임시 세션은 약관 동의를 다시 저장해야 등록증 인증·전화번호 인증을 진행할 수 있다. 기존 정식 회원의 동의 기록에는 이 검사를 적용하지 않는다.

| 상태 | 코드 | 의미 |
| --- | --- | --- |
| 400 | INVALID_INPUT | version 누락·공백·형식 오류, 기존 입력 검증 오류 |
| 409 | TERM_VERSION_MISMATCH | 실제 표시한 버전과 서버의 현재 버전이 다름 |
| 409 | TERM_RECONSENT_NOT_SUPPORTED | 기존 정식 동의 기록의 버전을 변경하려 함 |
| 503 | TERM_VERSION_UNAVAILABLE | 해당 약관의 현재 버전이 아직 설정되지 않음 |

기존 인증·필수 약관·약관 ID 오류 계약도 유지한다. 상세 응답은 Swagger를 참고한다.

## Flyway와 적용

- V37은 `term_type.current_version`, `user_term_agreement.term_version`, `social_auth_session_term_agreement.term_version`을 nullable로 추가한다.
- V38은 현재 버전이 없는 약관 항목의 `current_version`만 `v1`로 초기화한다. 이미 등록된 현재 버전은 덮어쓰지 않는다.
- 회원 및 가입 세션의 기존 동의 여부·시각·버전은 변경하지 않는다. 특히 버전 미기록 과거 동의를 임의로 v1 동의로 채우지 않는다.
- V38 적용 후 현재 약관 버전을 별도로 수동 등록할 필요는 없다. 프론트는 `v1` 본문과 요청의 `version: "v1"`을 함께 적용한다.
- V38 이후 새 약관 항목을 추가한다면 그 항목의 현재 버전을 함께 등록해야 한다. 버전이 없는 항목의 저장은 기존 검증에 따라 503으로 차단한다.

## 추후 검토 범위

현재는 v1 본문 표시와 동의 저장·조회까지만 사용한다. 아래 항목은 현재 구현 대상에 포함하지 않는다.

- 약관 개정 시 v2 이후 버전의 적용 시점, 프론트 본문과 백엔드 현재 버전의 동시 반영.
- 개정 전 본문 보관 및 과거 동의 기록과 본문을 연결하는 방법.
- 기존 회원의 재동의 필요 여부·대상·요청 시점·미동의 시 처리.
- 약관 본문을 버전별로 DB에서 관리하는 구조, 본문 조회 API와 관리 기능의 도입 여부.

개정 기능을 추가하더라도 과거 동의 기록을 새 버전 동의로 임의 변경하지 않는다.
